## 3. O6 来源账与独立复算

以原冻结计划的144个输入组合为唯一计划集。生成 GROUP_LEDGER.jsonl，每组一行：group_id、产品/工具/install/input/config身份、来源run和路径、原判定、有效性理由、替代/作废关系、样本数、预热边界、指标单位、P95/max、资源缺口及本代复算判定。

必须证明 run03 的116组与沿用run01的28组互斥、无缺项、无重复、并集恰为144；否则 affected 组为 not_evaluated，不补跑填表。沿用28组逐组证明未受工具缺陷影响，不能只引用“此前有效”。来源混合不计算跨组聚合速度或平均通过率。

判官直接读原逐样本数组，P95=sorted[ceil(0.95*n)-1]；每组30个评分样本、缺样为 not_evaluated；失败和边界样本不删除。保留原30k积分 P95<=500ms/max<=1000ms、100k P95<=2000ms/max<=5000ms，以及原O6查询/冷启动门，完整门表从冻结计划逐项抄入判官配置并核对，不改阈值。

指定真实失败 r01_b00_cuboid_c30000_o50_x50 必须保留，复算其原始样本；若与517.3ms摘要不一致，报告差异和原因，不择优选源。读视图/缓存字节 not_evaluated 不可由RSS通过代替。O6全矩阵PASS仅在144组所有强制门皆通过且资源覆盖完整时成立。

## 4. O7 窗口、容量和恢复账

逐窗复算9个正常窗及过载/恢复，不合并窗口掩盖失败。正常窗保持原120s、240输入、120查询链及既定查询门；检查每个固定计划ID的发送、接纳、完成、拒绝、超时、未完成和查询终态，重复ID/缺事件具名报错。成功子集与全部请求分别报告，失败不移出分母。

过载以600个计划输入为基集，分别在发送截止、30s排空截止、恢复截止建立互斥终态账。追踪所述77个未完成ID的最后状态，区分未发送、队列中、在途、已完成但未观测；缺证据标 unknown，不推断丢失或补造完成。恢复60帧和30次查询另账，首个STALE保留，并核对原合同是否允许，不因随后OK改写恢复通过。

integrate内部时间、外部请求时间、队列时间、实际完成吞吐、快照年龄分别统计。1/平均服务时间仅列估算，不称实测4-9Hz吞吐。outside/crossing指ULD域，不是单个行李箱。O5代表评测仅列来源和覆盖范围，正式O5未评估的状态不变。

## 5. Surface 诊断：先分段再归因

先审查O6/O7真实调用链、返回数据量、目标身份、冷/热缓存定义及计时边界，输出 SURFACE_PATHS.md。核实两者是否同一操作；若不同，不能将差值视为并发回归。

随后只跑1cm倒角、0/20箱、30k、outside=0.5/crossing=0的两组。每组冻结同一输入前缀，以相同查询序列对照：D0无写入固定快照；D1原2Hz写入并发。每臂3次预热+30次评分，按组交替D0/D1顺序，一轮不择优。每条记录实际快照身份、revision、surface大小及缓存状态；首读、命中、变化后读取分开，禁止将命中与重建混合解释。同输入前缀不等于D1每次读取身份相同。

使用外层脚手架/可撤销诊断适配器记录 scheduled/send/callback/result、线程CPU、锁等待（可观测时）、surface构建、拷贝/转换和序列化；不能观测的段标 unknown，残差不能命名为GIL或积分成本。产品事件需插桩时仅在独立诊断树，明确patch和产品diff，结果一律 not_scored，不换绑产品。不能无侵入分段时先交付现有证据，不自行改执行器或锁。

若用插桩，附同输入10对ON/OFF平衡AB/BA，报告扰动而不认证性能；扰动P95比>1.10时不以插桩绝对时延判门。诊断数据不能替代历史O7 FAIL。只将直接事件支持的关联标已观测，因果解释及替代解释分列。不预设积分、缓存、锁、调度任何一个是原因。
