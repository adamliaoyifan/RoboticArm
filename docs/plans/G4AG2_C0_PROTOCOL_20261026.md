## 2. 对象生命周期状态机（正确性前置，实现前冻结）

```
暂存(staging) → 已发布(published) → 接收中(receiving) → 已映射/解码(mapped)
                                                ↘ 查询持有(query-held) → 退役(retired) → 可回收(reclaimable)
```

边界（每条都是实现合同，违反即缺陷）：
- **接收成功 ACK ≠ 允许回收**（ACK 只报告映射完成，回收还需退役条件）。
- **发布新指针 ≠ 旧对象无人使用**（旧代查询持有中）。
- **token 过期 ≠ 可终止已运行查询**（活动引用保护优先于过期）。
- **缓存有界**：不得无限持有退役对象；预算（派生 512MiB）内驻留。
- **ACK 丢失**：安全保留；预算不足→**具名背压或不可用**（不阻塞事实提交、不突破 512MiB）。
- **故障注入中安全拒绝是正确行为；正常压力下频繁拒绝=性能验收失败**（两条分开判定，不得互相掩盖）。
- **先做确定性接收/回收竞态测试，再进杀进程与故障矩阵**（顺序冻结）。

## 3. 四轴报告口径（每代表组分别给出，不得合并成一个总时长）

1. **ROI 响应**（客户端往返，A7 门）；
2. **提交→READY**（可见性传播，1s/2s 门）；
3. **写入调用耗时**（apply_update 返回耗时，A8 门 ×1.10）；
4. **后台总 CPU**（导出编码+IO+接收解码线程 CPU 合计，I5/I6 计量）。

**定性收紧（用户 2026-10-26）**：
- "隔离后 ROI 主要剩余成本=传输"**未证明**——传输层首先影响的是后台 CPU
  与提交→READY 延迟，不得预写结论；
- 异步生命周期**不定性为"性能次要"**——同步编码/IO 可能直接决定写入
  P95 是否过门。
- 实施顺序（C0→C1→C2→C3）只是优先级，**不称"实际收益排名"**。
