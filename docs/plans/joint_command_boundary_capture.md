## 1. 保存哪些数据（五层同轴，不能用 reference 替代实际输出）

| 层 | 保存内容 | 来源与边界声明 |
|---|---|---|
| L1 输入轨迹 | 完整 FJT goal、UUID、关节顺序、位置/速度/加速度、纳秒时间、容差 | 复用 78c8941e 逐字捕获 |
| L2 JTC | 每周期采样 reference、实际写入 command interface 的值、所用状态、当前 goal | 〔修正1〕**不修改 JTC**——只能取得 50Hz 已发布状态（controller_state）＋插件侧实际读取值，**不能宣称直接观测了每次 JTC 写入**；controller_state 只作辅助互证，不代替实际接口证据 |
| L3 gz 插件 | 收到的指令、转换/限幅后的实际写入值、目标关节实体、跳过或失败原因 | vendor gz_ros2_control 插桩 write()。〔修正2〕插件读数是**插件接收边界的权威值**；实际调用频率、与 controller update 的顺序、是否存在其他写入者，须从安装版本源码及运行数据核实 |
| L4 物理反馈 | 实际关节位置/速度、有效的 effort、物理步编号及时间 | 插桩 read() + OnUpdate 心跳（iteration/simTime）；effort 无接口→原样 NaN |
| L5 上下文 | 控制器切换、其他指令写入、箱体跟随目标、实体变化、采集丢包与队列状态 | 控制器列表快照、复用 ELFIN_FOLLOW_TRACE follow 追踪、launch/driver 日志、health |

所有记录带源时间戳、时钟 epoch 和序列号。优先用控制周期编号关联；只能靠时间
匹配时，明确同步误差。NaN、空数组和不可获取字段原样保留。

**判定输出形态**〔修正3〕：产品回答"第一处偏差出现在 JTC 输出、插件写入，
还是实际物理响应"，但**允许输出"JTC 内部/接口间未分离"或"证据不足"**——
不强迫分析器在不可观测边界上归因。

## 2. 默认关闭，debug 按需打开

- off：只保留轻量运行摘要，不保存每周期数据。〔修正6〕off 的准确表述=
  无分配、无落盘、无额外线程/话题；**插桩分支仍可能有开销，需要测量**（§5 耗时门）。
- armed：有界内存环暂存（≥触发前 15 sim-s）；异常或手动触发后落盘。
- window：保存指定腿的完整执行及保持窗口（当前专项：触发前 15s＋后 60s
  仿真时间）。
- 600 秒墙钟截止：仿真暂停后不无限等待，截止即落盘并具名截断。
- 手动触发只保存证据，不修改控制参数。
- 〔收紧1〕控制目录 10Hz 轮询**仅在后台落盘线程执行**——控制/物理更新回调
  不能访问文件系统。手动服务触发与目录触发**统一事件编号与幂等规则**：
  事件以单调编号标识，同一事件只落一次盘，重复触发幂等返回首次结果。
- SIGTERM 尽力 flush；SIGKILL 尾损单列为残余缺口，不记正常退出。

## 3. 实机（复用同一记录格式，采集边界不同）

不能假定实机一定经过 JTC：经 JTC→采 JTC 输出、硬件接口发送指令和机器人
反馈；经厂商执行器→采厂商命令/应答及反馈；厂商内部伺服数据拿不到就标为
unknown，不把"命令收到"当成"电机已执行"。常态轻量摘要，专项手动高频 debug，
不默认长期全量落盘。

实机仅预留四个函数接口：`describe_backend()`（声明后端及可采字段）、
`record_command()`（记录实际下发指令）、`record_feedback()`（记录反馈）、
`record_event()`（记录状态变化和错误）。公共记录器不依赖 Gazebo；后端注册表
对未实现后端（如 elfin_vendor）**显式拒绝，不静默回退**。不接厂商 SDK、
不连实机、不做实机验收。

## 4. 不让记录器干扰控制

控制回调只向预分配队列写固定长度记录，不做磁盘写入、压缩或阻塞等待。后台
线程落盘；预算：**环形缓存 64MiB、写队列 32MiB、单次 256MiB**。满队列、磁盘
故障和截断**必须具名记录，不能静默丢数据**。〔修正6〕插桩分支本身的耗时
（off 时亦存在）按 §5 耗时门测量并记录。

## 5. 验收重点

**两档"无运动"**〔收紧2〕：纯离线单测 ≠ 静止仿真。真实 .so 加载、插件读写、
物理时钟的验收需要**静止仿真**（启动 gz+控制器栈、不发轨迹 goal）——是否
允许，实现轮前另行明确；纯单测不能替代这些验收。当前文档轮不启动仿真。

| 门 | 内容 |
|---|---|
| T1 版本/插桩核验 | 〔修正5〕同名 tag **不证明**与已安装 deb 源码/补丁/构建选项一致：保存来源仓库、提交哈希、补丁文件、构建选项，并比对**运行时实际加载 .so 的哈希**与水印自报；install/src 同步核验（本仓拷贝安装坑） |
| T2 字段无损+时钟 | 声明字段全在、NaN 原样、seq 连续、时戳单调；复位不串时钟（双会话 epoch/seq 干净重启） |
| T3 跨层关联 | 周期号连接为主；〔修正4〕50Hz×100Hz 只是**名义速率比例**——实际互证覆盖率取决于采样时刻、发布丢失及可关联性，**必须实测**并连同同步误差列如实报告 |
| T4 零丢弃 | 各层 dropped==failed==0 |
| T5 故障不阻塞 | 输出指向 /dev/full、强制环满：具名计数递增、控制路径无磁盘/阻塞；〔收紧3〕**插桩耗时门**：逐调用新增耗时分位数 vs 基线；**deadline miss 基线与开启后分别统计、不得新增**（弃用"无>50ms 缺口"——对 100Hz 循环过松） |
| T6 行为等价 | 〔收紧3〕静止输出一致**不能覆盖转换分支**：在**离线插件夹具**中测试变化指令、限幅、跳过写入、保留上一指令等行为，逐一与未插桩基线对拍；开启前后指令输出一致 |
| T7 触发语义 | 手动触发零控制参数改动（配置哈希断言）；600s 墙钟截止可触发并具名截断；事件编号幂等（重复触发不重落盘） |

## 6. 频率裁定（2026-10-21）

| 项 | 裁定 |
|---|---|
| 日志采集 50Hz | 可以：不改控制行为、数据量减半；但可能漏掉 100Hz 控制周期中的单拍异常 → 仅作日常查看/曲线展示降采样 |
| JTC 状态话题 50Hz | 当前配置已是 50Hz，维持；它发布的是控制器状态，不等于实际 command-interface 写入记录 |
| 控制频率 50Hz | 技术上可改，本轮不改：会改变控制行为，可能让原故障消失或变化，影响定位 |

**结论：保持 100Hz 控制；插件侧每次实际写入都记录；六关节定长数值记录不为
存储量舍弃一半周期；日常查看与曲线展示再降到 50Hz。**

## 7. 收缩方案的代价与非目标

保留"JTC 不 vendor、只插桩 Gazebo 插件"。代价（明示）：本轮能区分**插件
接收值、实际施加值和物理反馈**；**JTC 内部的单周期异常可能仍无法定位**；
controller_state 只作辅助互证，不代替实际接口证据。

非目标：控制器重写、参数调优（position_proportional_gain/update_rate/
state_publish_rate 全不动）、settle 门变更、厂商 SDK、机器人-环境接触与 gz
求解器内部观测（另行捕获面）。已知扰动（manifest 必列）：vendor 二进制遮蔽、
诊断 run 额外线程/话题、follow trace 落盘、50Hz 发布观测的混叠局限（实测覆盖率）。
