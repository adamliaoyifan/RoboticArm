## 1. 目标与明确约束

在有顶棚的 ULD 中增加一套与正常放置并行的 upper-layer place 动作。
复用已有 pick / offset pick。允许在柜外调整箱体角度，使 suction panel
朝上、位于箱体下方；先将箱体部分送入已有行李顶面，形成可释放的稳定支撑，
再释放吸盘、退出和调整机械臂，最后从后面直线推入目标位置。

第一版必须面向真实行李形成的起伏顶面，不能用理想水平板替代最终验收。
下层行李不得被主动整理、挪动、压平；不增加翻滚、越障或拨开行李的动作。
不满足支撑、退出、推入或观测条件时拒绝该候选。支持起伏表面不等于承诺任意
起伏均能成功；必须给出支持范围和范围外拒绝原因。

无触觉传感器。保留两个独立评估配置：A 为 RGB-D/已有几何传感器和关节位置；
B 额外允许已验证可用的原生关节电流或力矩反馈。B 的结果不能代替 A 的验收。
D555i 沿用仓库 D555 感知链命名；具体硬件型号、安装和标定在实测前核对。

本次只保存计划并清理工作树资料，不开发功能、不启动仿真或真实机械臂。
原有离线原型保留为研究工具；它没有验证完整手臂连续轨迹或接触物理，不能作为
本计划已完成的证据。此前 G1 的冻结范围和结果由 Git 历史及主工作区记录保存。

## 2. 何时使用上层动作

在 COMPUTE_PLACEMENT 阶段、EXEC_PICK 之前联合选择：
`(目标位姿, 抓取接触位置/偏置, 动作类型)`。

1. 获取同一 geometry_hash / map_revision 下的目标空间与局部支撑快照。
2. 生成几何放置候选；不提前用旧的吸盘朝下动作限制筛掉全部上层候选。
3. 分别评估 normal-place 与 upper-layer-place。正常动作可行时第一版优先正常动作。
4. 正常动作不可行、且上层动作的支撑、完整轨迹、推入和可观测性检查通过，才选择上层动作。
5. 数据不足返回 NEED_OBSERVATION，由已有观察流程补观测；两类动作都无可执行候选则报告原因。

装载比例、层号、一次规划超时或 BIN_FULL 都不能单独触发上层动作。
已经抓取时必须采用实际 tool-to-box 变换重新评估；不能假定能在空中更换抓取偏置。
需要重新抓取时走显式恢复流程，不隐含增加动作。

## 3. 感知与 planner 的职责

结论：保留相机底层链路，补充局部场景表达和可观测性；仅修改 planner 不足。
现有最高占据高度和箱体检测不能完整描述支撑接触区、空洞、台阶和工具退出通道。

| 层级 | 拟新增或复用 | 输入 → 输出 | 责任边界 |
|---|---|---|---|
| 相机链路 | 复用同步 RGB、对齐深度、CameraInfo、预处理状态 | 同次采集数据 → 合法观测 | 不新增第二套同步，不绕过 canonical preprocessor |
| 地图 | 复用 cargo_volume_mapper；必要时增加只读 ROI 快照接口 | ROI、预期版本 → occupied/free/unknown、来源和版本 | 地图仍由现有模块唯一维护 |
| 局部支撑几何 | 新增 local_support_geometry.py | 场景快照 → 表面样本、法向、区域、边缘、台阶、缺口和质量 | 不判断力学承载能力，不输出最终 can_place |
| 候选生成 | 新增 upper_layer_candidates.py | 局部几何、箱体、合法抓取、质心范围 → 候选 | 负责箱体相关的接触和几何约束 |
| 动作规划 | 新增 upper_layer_motion_planner.py | 候选、机器人模型 → 连续轨迹或拒绝原因 | 完整机械臂、末端、箱体及阶段接触约束 |
| 下层运动监测 | 新增 support_motion_monitor.py | 基线和新观测 → 运动证据及可观测状态 | 不把看不见误报为静止 |
| 编排 | 扩展现有动作选择/执行流程 | 动作结果 → 继续、补观测、停止或恢复 | 感知查询不得自行驱动机器人 |

优先实现 ROS-free 纯函数 `extract_support_geometry(snapshot, roi, config)`。
监测器需要历史状态时使用 `update(data, stamp, frame_id)` / `copy_output()`，
返回独立副本。ROS 节点只承担消息、TF、服务与生命周期适配，不继续扩张大节点。
已有 top_support_estimator / dynamic_top_surface 的通用几何可以复用，
但不能将整个多行李支撑面拟合成单一平面。现有单箱 tracker 不能直接证明多箱静止。

## 4. 接口草案

先定义进程内类型；实现前检查分支已有查询能力，避免重复接口。
只有跨进程确有需要时才在 luggage_msgs 增加消息或服务。

`LocalSupportSnapshot` 至少包含：

- snapshot_id、frame_id、geometry_hash、map_revision；各视图采集时间及新鲜度。
- ROI、实际分辨率、表面采样/局部网格、法向、连通区域、边界、台阶和缺口。
- 有效掩码、覆盖率、观测来源、质量信息与可追溯的不确定性估计。
- 同一快照的局部 occupied/free/unknown 数据或稳定的只读查询句柄。
- 几何顶棚距离与已观测自由空间分别表达，不能用前者代替后者。

可选服务草案：`GetLocalSupportGeometry(roi, expected_revision, geometry_hash)`
返回快照、实际版本、valid、reason。版本不一致、数据过期或空间未知均显式返回。
细化栅格不能自动提升深度精度；平面残差不能直接当成距离误差界。
未分类的障碍物仍必须进入碰撞检查。

`UpperLayerCandidate` 包含 final_box_pose、handoff_box_pose、push_direction、
合法 suction_contact / tool_to_box、临时和最终接触区域、支撑假设、退出/重定位通道、
snapshot_id，以及各检查状态。最终位姿、临时承托位姿与推入路径不能只用一个 SlotSpec 表达。
保持 DetectedLuggage 描述待抓箱体，不向其中塞入目标行李堆地形。

`SupportMotionObservation` 输出 `MOTION_DETECTED`、`NO_MOTION_OBSERVED` 或
`NOT_OBSERVABLE`，并提供区域、时间、位移估计、误差和覆盖率。
基于原始/近期观测、时间对齐和相机运动补偿，屏蔽机械臂及目标箱体；不能仅比较平滑地图。
panel 朝上和推入时必须检查实际视野。相机遮挡不能靠新增 class 消除。

## 5. 动作与失败边界

阶段：柜外翻转 → 向上承托接近 → 部分插入 → 稳定承托检查 → 释放 →
向下/向外退出 → 连续调整到后侧 → 低速直线推入 → 最终复测。
每个阶段明确允许接触的对象及面，其他接触仍为碰撞；不得为解决卡住放开整箱碰撞。
检查完整手臂、吸盘、转接件、相机、雷达和负载的扫掠体，包括姿态切换。
阶段 IK 存在不能证明阶段之间连通。

临时承托不是“插入一半”固定比例。依据真实抓取位置、箱体质心包络、有效接触区和
抗倾覆余量求可行区间，同时保留吸盘退出空间。起伏接触可能使箱体倾斜，必须检查
倾斜后顶棚间隙和后续直推路径；需要越过台阶或重新摆正才可推入的候选在 V1 拒绝。

RGB-D 不能直接给出重量、内部质心、摩擦、软箱变形、承载能力和吸盘抗剥离能力。
必须定义这些参数的可验证范围，并进行范围内鲁棒检查，不能从点云编造力学参数。
只有视觉的配置不能声称具备力控或保证接触力；停止延迟及可检测位移限制必须实测。

发现下层移动、失去关键观测、目标滑落趋势、版本失效或执行异常时停止推进并进入
阶段相关恢复。释放前保持真空；释放后不能假设仍附着，恢复策略必须单独验证。
不得自动重复推入或通过更大推力完成动作。

## 6. 分阶段实施与验收设计

以下是设计阶段的工作划分，尚未派发。各阶段由同一实施责任人完成代码、测试、修复和记录；
派发时补齐具体 owner/model、精确 plan_revision、代码基线和命令。当前不使用未存在的测试命令假装可运行。

| 阶段 | 工作 | 必须观察到的结果 |
|---|---|---|
| P0 参数与测量 | 核对资产、标定、载荷范围、可见性和反馈能力；固定评价配置 | 每个阈值有来源/测量方法，观测误差和停止延迟已测，两个传感器配置独立 |
| P1 感知离线回放 | 局部快照、几何提取、下层运动监测 | 时间/版本错误与 unknown 被拒绝；缺口和台阶保留；运动与不可观测明确区分 |
| P2 候选与完整轨迹 | 联合抓取、交接、退出、后推规划 | 有效轨迹覆盖全部阶段；拒绝碰撞和不稳定候选；正常放置不回归 |
| P3 仿真物理 | 起伏多行李、顶棚、真实末端，先固定几何后传感器闭环 | 下层可自由运动，动作成功不能来自锁定支撑；GT 仅用于造场景和评分 |
| P4 受控实物 | 在锁定的材料/重量/质心/摩擦范围内验证 | 校验仿真偏差和传感器配置限制，达到冻结的位移、成功率和停止阈值 |
| P5 集成 | 选择、执行、异常恢复与原有 pick/offset pick 回归 | 只有完整可执行候选才触发上层动作，异常可追溯，不偷偷添加整理动作 |

P1/P2 的确定性契约案例每项至少一个正例和一个独立构造反例，全部通过；
它们证明契约行为，不用于宣称现场成功率。对未采集到的测量项输出 not_evaluated。

P3 必须先建设专用场景。至少覆盖：均匀顶面作对照、不同高度错位箱体、横向坡度、
推入方向台阶、跨缝支撑、可变形表面、低摩擦可滑支撑、可滚动/不稳定支撑、
顶棚过低、退出通道不足、遮挡/深度缺失、地图版本改变。
将预期可执行与预期拒绝分开；不能靠全部拒绝通过验收。

矩阵另外交叉箱体尺寸、合法中心/偏置抓取、允许质心包络、顶棚间隙与 A/B 配置。
具体数值及削减组合必须在 P0 形成固定 manifest；不要直接继承 G1 的理想平面阈值。
先进行可重复的非计分接线/启动演练，再冻结场景、随机种子、模型、命令和代码 hash 评分。
计分中不得修改被认证产物；启动前失败不消耗场景种子，但记录发生率和耗时。

## 7. 派发前必须冻结的验收表

“下层行李不动”是需求；有限精度测量只能报告位移上界，不能宣称数学意义零运动。
当前不擅自替用户把 5 mm 或其他容差视为已接受。下表是 dispatch_ready=no 的具体原因。

| 指标/参数 | 冻结方法和必须记录的字段 |
|---|---|
| 下层位移与转角 | 每件支撑行李从接触前至结束的最大平移/转角及测量误差；允许上界需明确，不能只比较最终位置 |
| 可观测性 | 各动作阶段的可见覆盖、深度有效率、最长盲区、新鲜度限值、低于限值的停止行为 |
| 几何误差/余量 | 标定与深度误差、栅格尺寸、碰撞裕度、交接支撑裕度和倾角限制；误差必须小于对应决策余量 |
| 接触范围 | 重量、质心包络、材料、摩擦/柔顺性范围、吸盘负载范围，以及 A/B 各自停止速度和距离 |
| 完成质量 | 最终位姿误差、稳定时间、超时、允许接触及禁止事件；箱体全部进入目标容积 |
| 可靠性 | 每个场景族与传感器配置的目标单次成功率、重复数、随机种子、置信界和聚合规则 |
| 拒绝能力 | 无效候选误接受率、有效候选误拒绝率和最小有效样本数；分场景报告，不能只看总体平均 |
| 性能 | 分阶段延迟、停止响应和最大执行时间，明确硬件与软件环境 |

可靠性采用每个配置/场景族分别统计的二项成功率置信界，目标和样本数先冻结。
若使用连续 N 次全过，必须说明其通过概率为 p^N，验证门槛能区分可接受与不可接受的
单次成功率；不得把大量样本全部通过当成随意指定的质量指标。缺少最小样本时结果为
not_evaluated，不能按零失败计成功。危险事件与感知/规划失败分别报告。

尚待确定：实际重量/质心先验来源；原生力矩反馈可用性；下层位移的可接受测量界；
不同姿态下相机是否能持续看见支撑；最小有用的可执行起伏场景范围。
这些信息决定实现与验收范围，不能用 planner 参数默认值替代。

## 10. 已授权先行项：对齐密铺仿真场景（2026-11-11）

此项可以独立执行，不代表前述动作算法或产品验收已具备派发条件。
Owner: eng/codex/gpt-6；基线为本文件 base_revision；使用当前 worktree，保留既有资料清理。
新增研究场景生成器及必要的通用 world_sdf 启动参数，不实现自动放置或改动 pick。

固定场景使用原始场景的 ULD 网格、位姿和七面体内轮廓。4 层、每层 3 个深度列和
2 个宽度行，共 24 个对齐的独立动力学箱体；侧面按 chamfer 收缩底层尺寸。
测试载荷使用 carryon 行的 0.55 × 0.40 × 0.25 m；上层余量为箱高加 0.03 m，
期望支撑面 z=1.73 m、可用顶层高度 0.28 m。合成下层箱体不是新增的实物尺寸先验。
保留正常机器人、传感器、平台与箱体生成服务；默认不发任何机械臂运动命令。

验收为一次确定性场景构建和一次 5 s 仿真时间的无外力稳定性检查：
所有箱体完整包含于规范 hull，无互穿；顶层平齐；顶部净空满足箱体而不足以容纳
吸盘朝下的完整固定末端；按 hull 裁剪的底部填充率至少 90%；下层无 static/fixed joint。
物理检查中相对初始位姿最大水平位移 ≤ 0.003 m、竖直沉降 ≤ 0.010 m、姿态角 ≤ 0.01 rad；
这只验场景搭建和重力稳定性，不证明推入时下层不动或动作成功率。
同时做完整栈启动演练：S20 生成且 arm_controller active；不评分运动/感知表现。

程序/验证入口定为 `research/uld_upper_layer/scene.py` 和
`research/uld_upper_layer/tests/test_scene.py`；构建命令为

### 11.1 用户确认的第一版假设与范围

- 用户“重心在重心位置”结合前文明确解释为：V1 待放规则箱的重心默认位于
  箱体几何中心（box 局部几何中心坐标为 [0, 0, 0]）。这是假设，不是 RGB-D
  测量结果；后续真实装载箱重新估计重心/不确定区间，接口预留来源与估计版本。
  仿真规则箱质量中心与该声明保持一致，真实未知重量分布不在本次承诺内。
- 第一版针对第 10 节对齐密铺、顶面近似共面的独立动力学箱体；真实起伏行李
  保留为后续阶段，不再作为本次首个动作验收的必过正例。超范围顶面应拒绝，
  不通过拟合平均平面掩盖台阶或缺口。
- 支撑比例定义为：当前箱底平面上实际可提供支撑的接触区域并集面积 / 箱底
  总面积。允许多件下层箱子共同支撑，重叠不重复计数，缝隙和 unknown 不计入。
  比例 >= 0.60；重心投影位于有效支撑区域内，至其边界的最小距离 >= 0.020 m。
  两个条件同时满足；裕量距离是箱底平面内长度，不是世界 XY 的隐式距离。
  第一版以这个保守的实际支撑区域判据为准，不自动以凸包跨越缺口放宽。
- “完成接触”指满足比例的部分箱底接触支撑，允许箱尾悬空，并非全箱底贴合。
  吸盘先承重，受控下放建立上述接触后才解除真空，再脱离与撤出。
  不要求从几何推断释放前的承重比例，不设置无传感器依据的重量转移阈值。
- 释放后默认箱子不沉降、不倾斜、不滑动，作为本次规划假设明确输出；仿真若
  观测到违反则记录失败/假设失效，不锁箱、不瞬移、不关闭重力来维持假设。
- 不使用关节电流或力矩反馈，也不开发其分支；不声称具备力控。使用现有
  D555i/D555 命名链路、已有合法几何传感器与关节位置反馈。原 A/B 双配置
  对比移至未来真机测量后考虑。
- 不重新抓取、不换抓、不主动调整下层、不滚动/摆动/反复试推。柜外允许选择
  翻转轴和角度；第一版正面水平直线插入，交接时箱底与支撑面平行，插入
  上层时 panel 不朝下。后侧单方向直推，保持简单动作顺序。
- 使用 suction panel 的实际平面推箱。推压位置、panel 姿态及接触区域由下节
  几何方案确定，不能随意用支架或虚构推杆替代。
- 首个动作实验使用明确的已抓取状态和实际 tool_to_box 变换；若初始抓取
  不兼容则拒绝，不在空中修改偏置。后续接入 EXEC_PICK 前的联合选择。
- 首轮限制一个由场景配置指定的目标 ROI，ROI 内仍由测得几何搜索交接点和
  最终位置；配置 ROI 不等于硬编码最终位姿或固定关节轨迹。

### 11.2 配置必须真实进入决策

拟定独立 UpperLayerConfig，默认字段：

| 参数 | 默认值 | 实际影响 |
|---|---|---|
| support_area_ratio_min | 0.60 | 交接候选的有效接触面积门槛 |
| support_com_margin_m | 0.020 | 重心投影至有效支撑边界的最小距离 |
| com_model | geometric_center | 提供带来源的 V1 重心假设 |
| target_roi | 场景配置中的一个区域 | 限制搜索范围，不提供解 |

全部数值只有一个权威默认配置入口，不在感知、候选、轨迹和执行模块中重复
写常数。ROS 参数/外部 YAML 经有类型、有单位的配置对象传递；无需重新编译
即可加载新配置。运行中参数更新先整体验证，非法值（非有限数、比例不在
(0,1]、负裕量等）拒绝且保留旧配置。每次规划冻结 config_revision/hash，
生成候选、支撑检查、轨迹校验与执行准入采用同一版本。影响安全/可行性的
参数更新使尚未执行的旧计划失效并重新规划；执行中不静默切换阈值。
感知输出原始几何与误差，不能用规划裕量改写表面测量。

必须做行为验证：固定相同感知快照、抓取状态与其他配置，构造重心边界距离
为 0.015 m 的可评分正向案例；margin=0.010 m 时通过该支撑门槛，
margin=0.020 m 时因 COM_SUPPORT_MARGIN 拒绝。另有全链路可行案例证明
降低阈值确实产生计划、提高阈值确实拒绝该候选或选择另一合法计划；不得靠
两次都失败、只检查参数回显或源文件文本来证明参数生效。以同一构建产物
更新参数并重新查询，记录输入、配置 hash、候选/拒绝原因和最终规划结果。
不承诺任意阈值变化都必然改变路径，要求跨边界案例证明决策依赖真实存在。
比例阈值同样设置独立跨边界案例。

### 12.2 数据所有权与输出分层

| 类型 | 内容与所有者 | 跨模块规则 |
|---|---|---|
| SceneSnapshot | 地图/感知拥有的 OCC、支撑面、TF、误差与版本 | 算法只读，查询绑定同一快照 |
| BoxState | 箱体尺寸、当前几何中心位姿、重心模型与来源 | 候选模块不能改观测尺寸/位姿以过关 |
| GraspInput | 未抓取的合法接触区域或已抓取的实际变换 | 显式区分 SELECTABLE 与 FIXED；禁止隐式换抓 |
| RobotState | 真实起点关节状态及时间、机器人/工具模型版本 | 完整动作必须连接实际起点 |
| PlacementRequest | ROI、允许朝向/动作、搜索预算 | 每次请求冻结，扩展不越界 |
| UpperLayerConfig | 支撑、搜索、去重、容差与停止参数 | 统一校验/版本化配置，无跨模块裸 setter |
| PlacementCandidate | 最终箱体位姿、支撑区域与指标 | 唯一 ID、输入版本，生成后不可原地修改 |
| ActionCandidate | 放置候选 ID、抓取变换、交接位姿、推压接触与方向 | 一个放置候选对应多个动作候选 |
| ExecutablePlan | 整条关节轨迹、事件、候选关联和校验证据 | 不得把未验证的阶段结果计为完整方案 |
| SolutionSet | 多个去重后的 ExecutablePlan 与搜索状态 | 默认 target=3，记录 achieved/target |
| PlanningReport | 分层拒绝、超时、尝试数、分阶段耗时、终止原因 | 可查询、可回放，不暴露可变内部容器 |

所有放置/交接 pose 指箱体几何中心，吸取 TCP、吸附面、推压面分开命名。
BoxState/候选通过显式 frame_id 和刚体变换关联，尺寸/角度单位明确；container
几何用绝对 Z，旧 floor-relative 接口只在边界显式转换，不将坐标放进尺寸字段。
抓持阶段使用固定 box-to-tool 变换；释放后工具与箱体解耦；推压为接触模式，
不能伪造持续吸附。候选姿态或配置变化必须重新校验并生成新标识。

### 12.3 接口、私有状态与搜索编排

优先窄的进程内类型和接口，跨进程需要才增加 ROS 消息/服务：
读取场景/箱体/抓取/机器人快照；开始候选搜索；获取下一批候选；规划动作候选；
获取 SolutionSet/PlanningReport；更新校验后的配置；检查计划执行准入。
入口负责时间/坐标/版本一致性，各算法不得独立拼接异步最新值。
候选是分批、可续取的搜索结果；外层最终位姿与内层抓取/交接/推压搜索需要
交替推进，不能在生成固定少量放置 pose 后永久丢弃其他空间。

公开可改：任务 ROI/动作范围/预算（请求），目标方案数、枚举/细化步长、批大小、
去重距离/角度、排序策略及阈值（配置）。实际物理状态通过拥有者更新，
禁止通过配置接口覆写。所有默认值集中声明，安全约束不由搜索策略私自放宽。

私有：空间索引、加速场、枚举游标、已尝试集合、IK/碰撞缓存、规划器搜索树、
临时排序数据。内部缓存键包含快照、模型、抓取和配置版本；版本变化失效。
外部仅查询统计/诊断，不持有可修改内部对象。排序规则与去重语义需明确，
不能用隐藏魔法常量决定是否计入三解。

计数按任务方案差异：最终箱体位姿、抓取、交接、推压的差异之一超过各自配置
的几何阈值，且完整轨迹已校验，方可作为独立方案；单纯关节轨迹随机抖动或
相同输入重复求解不自动成为新方案。阈值具体数值在实现任务中冻结并行为验证。
动作失败只淘汰对应组合，除非有几何证据证明整个放置候选不可行；规划超时
不得当作不可达证明。结果区分 TARGET_REACHED、BUDGET_EXHAUSTED、
SEARCH_EXHAUSTED（仅对已声明离散搜索范围）、NEED_OBSERVATION 和
INPUT_INVALID；同时返回有效解数量，不用一个 success 布尔值掩盖差异。

### 12.4 待具体化事项与设计验收

仍需讨论：目标数量不足时能否执行、多个有效方案的执行选择策略，以及搜索
微调范围/离散步长/预算/去重阈值的数值。当前不假定用户接受不足三条的执行。
这些问题不阻碍已确认的接口设计记录，不以未经讨论的数值补齐。

后续行为案例必须覆盖：首个放置/动作候选失败后继续找到解；同位置不同
交接/推压产生多解；重复近邻不能凑三条；ROI 内微调恢复可行；固定抓取模式
不换抓；预算终止与穷尽有区别；版本变化使旧候选/计划失效；真实起点到 pick
及全动作连通。每项的输入、预期观察、命令和证据须在可运行任务派发前冻结。


## 13. V1 搜索停止与执行选择修订 G6（2026-11-11）

本节记录用户确认，替代第 12.4 节对应未决项。仍仅更新设计，不启动实现或仿真。

- solution_count_target 默认 3，为提前停止搜索的目标数量；
  minimum_executable_solutions 默认 1，为允许进入执行准入的最低解数。
  找到第一条后仍继续搜索，直到达到目标、预算耗尽或声明的搜索范围穷尽。
- 预算耗尽或搜索穷尽时，已有 1–2 条完整可执行方案也允许选择执行；
  必须保留真实终止原因、achieved/target，不将预算耗尽伪装为达到三解。
  0 条时不执行；候选、单段 IK 或未校验路径不计入最低数量。
- 初期允许较宽裕但有限、可配置的搜索预算；具体墙钟时间、候选数上限和
  规划器单次预算在实现任务冻结前明确，不在本次讨论中虚构数值。
  搜索期间不驱动机械臂；长搜索结束后必须检查机器人起点、场景、抓取和配置
  有效性，失效则重验证/重规划，不能因为已经找到一条就执行过期轨迹。
- 第一版选择仅关注支撑和碰撞裕量：支撑面积比例、COM 边缘距离与完整轨迹

  各硬门槛仍须全部通过，不能用较大的某项裕量抵消另一项违规。
  多裕量的比较规则须显式可解释，不用隐藏混合权重；具体比较规则继续在
  接口/实现设计中明确，不能擅自将用户确认解释成某种加权公式。
- 动作复杂度和耗时暂不作为方案优选目标，留待后续优化；超时、速度/加速度

- 后续行为验证增加：目标三条但预算结束仅一条时可执行；零条拒绝；

  选择依据可追溯至支撑/碰撞裕量；过期方案即使数量满足也拒绝执行。

本轮已无待用户选择的最低解数或复杂度/耗时排序问题。剩余工程细节为具体
预算、采样/微调/去重参数及多项裕量的明确比较规则，后续设计需公开说明。


## 14. 候选与联合搜索接口草案 G7（2026-11-11，待接口评审）

本节为数据契约提案，不是已有 API/ROS service，不派发实现。第 11–13 节
用户确认仍适用。优先定义 ROS-free 类型和 Protocol，节点适配已有接口；
不因本草案新建第二地图所有者、生产编排器或通用巨型 manager。

### 14.1 公共类型与坐标约定

不可变 DTO：字段只读，数组 detached/read-only，引用的几何 blob 内容寻址且
生命周期显式，不将 mutable mapper/缓存暴露给消费者。公共记录带 schema_version。
长度 m、角度 rad、姿态为刚体变换/单位四元数；所有 pose 明确 parent/child frame。
box 原点为几何中心、轴绑定尺寸顺序；tool_tcp、suction_contact、panel_push_surface
为不同 frame，其固定变换来自工具模型。container 坐标为绝对 Z，尺寸不携带坐标。

| 类型 | 建议字段 | 生产者 → 消费者 |
|---|---|---|
| InputIdentity | snapshot_id、map epoch/revision/digests/schema、geometry_hash、TF/calibration/model/tool/config IDs、box_id/generation、acquisition stamps | 输入适配器 → 全链路 |
| SceneSnapshot | identity、source_kind、ROI、grid layout、occupied/free/unknown 数据、表面几何、误差/覆盖/完整性、显式 TF | SceneSnapshotProvider → 支撑提取、候选、私有规划场景 |
| SupportRegion | region_id、snapshot_id、surface frame/pose、局部边界/holes 或面片、法向、误差/来源 | SupportGeometryExtractor → 放置/交接生成与支撑验证 |
| BoxState | box_id/generation、dimensions、container_T_box、COM local xyz/model/source、测量来源与误差 | 箱体输入适配器 → 抓取/候选/轨迹 |
| GraspInput | SELECTABLE(合法接触面/区域、可用吸附模型) 或 FIXED(实际 box_T_tool、附着 identity/status) | 感知/抓取提供者 → 联合搜索/轨迹/执行准入 |
| RobotContext | q_start/关节名/stamp、robot_model_id、tool_model_id、控制器插值/限位配置引用 | 机器人/模型适配器 → 轨迹/认证 |
| PlanningRequest | request_id、目标 ROI、朝向/动作许可、refinement bounds、搜索预算、目标 3/minimum 1、配置版本 | 现有编排 → 联合搜索 |
| PlanningContext | 上述一致输入的不可变集合、context_id/digest、ready/reason | ContextBuilder → 各算法接口 |

SupportRegion 不强制绑定某件下层箱体实例；外露表面和障碍几何充分时可计算。
面积按多区域并集，holes/unknown 不算支撑；V1 默认几何中心 COM 与 60%/20mm
门槛均带配置来源。source_kind 显式区分 measured 与 ideal_sim_fixture，不能将
理想仿真数据标成实测；理想输入可用于用户允许的算法实验，不能冒充真实感知
链验收。替换数据源应保持 OCC/表面契约一致，算法中不得按场景 ID 换答案。

### 14.2 候选与结果类型

PlacementCandidate:
- placement_id、context_id、final_box_pose（箱体中心）。
- final_support（region refs、接触 patch、area_ratio、COM boundary distance）。
- box/hull/occupancy checks、测得净空、误差说明和几何阶段状态。
- 它只表示最终几何候选，不宣称可抓取、可交接或全臂可达。

ActionCandidate:
- action_id、placement_id、context_id。
- grasp：grasp_id、box_T_tool、接触 footprint、抓取模式与合法性来源。
- pick_box_pose 和由它/抓取变换计算的 pick_tool_pose；不能预置任意关节答案。
- handoff_box_pose、handoff_support、panel 脱离约束。
- PushContact：真实 panel surface_id、box 后侧 patch、panel-to-box 接触变换、
  push direction/distance、姿态约束和允许接触对象/面。
- 阶段约束序列与允许微调范围；生成后不可原地改写。任何 refinement 产出
  新 ID/parent_id，重算支撑与碰撞。不同 IK 分支属于后续路径求解，不靠随机
  关节扰动把同一动作凑成三解。

SupportMetrics:
- handoff/final area_ratio、COM margin，以及需要保持支撑的推入过程最低值。
- 各指标 validity/coverage/error；不将 not_evaluated 当作安全的零误差。

MotionPlan:
- plan_id、context_id、action_id、起点、完整有序 StageTrajectory 序列。
- 阶段含 timed joint path、受控事件、前/后置条件和接触模式；事件含 pick
  吸附/附着确认、交接释放、撤出/推压等，不能只给几个 TCP waypoint。
- 分阶段私有规划场景 identity，验证记录与证书 validity/assumptions。
- 完整路径最小禁止碰撞间隙及见证、SupportMetrics、采用配置和模型版本。
- 初次预测 grasp 的计划必须在实际 pick 后经实际附着几何重验证；其 READY
  是计划级完整性，不等于允许跳过所有阶段执行门。物理成功率需独立实验证据。

SolutionSet:
- session_id/context_id、去重后的 MotionPlan 列表、achieved/target/minimum。
- termination：TARGET_REACHED / BUDGET_EXHAUSTED / SEARCH_EXHAUSTED /
  NEED_OBSERVATION / INPUT_INVALID / CANCELLED / INTERNAL_ERROR。
- minimum_met、validation_summary、诊断引用。搜索状态与执行许可分开，
  不在此类型提供一个误导性的全局 can_execute。

PlanningAttempt:
- attempt_id、candidate/plan refs、stage、outcome、reason、duration/work counts、
  collision/support/IK witness refs；区分确定几何拒绝、超时、未检查和内部故障。

### 14.3 建议接口与调用方

以下为接口语义草案，名称尚未代表真实函数；支持 typed Result[T, Error]，
错误含稳定 code、identity、stage 与可诊断信息，不返回 None/空列表掩盖故障。

| 接口 | 输入 | 输出 | 谁调用 / 是否有动作副作用 |
|---|---|---|---|---|
| SceneSnapshotProvider.capture | ROI、期望 identity、采集/导出预算 | detached SceneSnapshot 或 mismatch/expired/incomplete | 输入准备；只读 |
| SupportGeometryExtractor.extract | SceneSnapshot、几何配置 | SupportRegion 集合与提取报告 | ContextBuilder；纯计算 |
| ContextBuilder.build | snapshot、box/grasp/robot、request/config | PlanningContext 或不一致原因 | 编排适配器；无动作 |
| PlacementEnumerator.open/next/close | context；cursor、batch/work budget | 分批 PlacementCandidate、下一 cursor、scope exhausted | 联合搜索；无动作 |
| ActionEnumerator.open/next/close | context、placement；cursor/budget | 分批 ActionCandidate、cursor、scope status | 联合搜索；无动作 |
| MotionPlanner.plan | context、ActionCandidate、独立 attempt budget/cancel | 完整 MotionPlan 或 PlanningAttempt | 联合搜索；只构造私有场景、无动作 |
| SolutionValidator.validate | context、MotionPlan、校验 profile | ValidationReport/证书或拒绝原因 | 联合搜索；无动作 |
| JointSearch.start/advance/result/cancel/close | context；session_id、bounded work budget | SearchUpdate / SolutionSet / PlanningReport | 现有编排；无动作 |
| SolutionSelector.select | 已验证 SolutionSet、显式裕量比较策略 | selected plan_id、各指标与选择解释 | 编排；无动作 |
| ExecutionAdmission.check | selected plan、当前机器人/场景/抓取/配置 | 阶段绑定 admission token 或 REVALIDATE/REPLAN/拒绝 | 现有执行编排；只检查 |
| ExecutionAdapter.execute/cancel/status | selected plan、有效 token、现有操作授权 | correlated execution events/results | 现有执行状态机；唯一运动/真空副作用边界 |
| ConfigProvider.read/update | scope/version 或 typed atomic patch/expected version | immutable ConfigSnapshot 或验证/版本冲突错误 | 配置适配器；不直接运动 |

公开 API 可以保留上述职责而合并进同一进程，不能为每行都机械创建 ROS node。
advance 是受预算约束的可取消计算，不以执行器状态轮询驱动候选算法。
next 空批次不代表穷尽：必须显式区分本次预算不足、过滤无结果与 scope exhausted。
规划尝试反馈只提供候选/阶段/失败证据，不允许枚举器擅自放宽硬阈值。
搜索交替推进外层 placement 和内层 grasp/handoff/push，避免一个位置耗光全部预算。
会话与分页 cursor 绑定 context/config/参数，跨会话或版本使用明确拒绝。

### 14.4 生命周期与失效

1. 输入阶段：适配器获得机器人/箱体/地图 identity 并校验时间和变换。
   现有 OCC `acquire_query_snapshot` 是五秒句柄、仅保留两个 generation；
   不能假定随长搜索永久有效。capture 必须在句柄有效时复制完整且版本一致
   的有限 ROI/相邻运动相关空间到 owned immutable snapshot，再关闭 owner
   handle。跨页 identity 改变、过期、内存/时间上限或不完整即失败；不拼新旧页。
   超出已导出空间的路径视为未覆盖，需重新 capture/context，不静默访问最新图。
2. 搜索阶段：PlanningContext 持有 snapshot，搜索期间不变且不阻塞地图更新。
   候选属于 context；cursor/cache 属于 session，不对外暴露可变引用。候选可
   导出报告，但只能在匹配 context 下继续求解。新配置产生新 context/session。
3. 方案阶段：MotionPlan/证书绑定输入、实际起点和模型。SolutionSet 只持有
   完整合格方案引用；达到三解或预算/范围终止，保留不足三解但至少一解的结果。
4. 准入阶段：选择后检查现场。新地图 revision 不证明旧场景仍有效，也不必
   一概宣称物理失效；通过相关 ROI/路径与证书规则重验证才可继续。起点/工具/
   箱体/抓取/配置不匹配必须拒绝或重规划，不改写旧计划掩盖差异。
5. 执行阶段：授权来自已有编排，重复请求不可重复驱动；按阶段确认实际附着、
   释放和后续路径。实际 pick 变换与预测不同需实际几何重验证，失败停在合法
   阶段；不能混入另一套候选后半段。执行后的旧起点 token 不可再次使用。
   取消等待控制器终态；通信异常不能等于已经停住。
6. 结束阶段：close/cancel 释放 cursor、planner/缓存和 snapshot 强引用；失败
   先保留需要的边界输入输出，再清理。被选方案的几何/配置依赖在执行终止与
   证据持久化前保持有效引用，不能因关闭搜索会话删除正在执行的依赖。
   报告/证据为只读历史，不作为下一轮自动可执行计划。

公共配置：support_area_ratio_min=0.60、support_com_margin_m=0.020、
solution_count_target=3、minimum_executable_solutions=1、ROI/微调界、采样/
批大小/去重、预算、容差和裕量比较策略。版本化整体更新，消费者不持有
ConfigProvider 的可变对象。执行中不静默热切换；未执行计划重新准入。

## 15. 裕量冲突的选择规则修订 G8（2026-11-11）

用户明确：支撑裕量与碰撞裕量冲突时，优先避免机械臂碰撞。
本节取代第 13–14 节对应未决项，仍为设计更新，不启动开发/运行。

- 准入先于排序：支撑比例、COM 裕量、箱体稳定假设、全臂/工具/载荷禁止
  碰撞和其他硬约束必须全部满足。机械臂间隙更大不能补偿支撑不合格，
  支撑更好也不能使碰撞方案进入可执行集合。
- 合格方案中，首先比较完整轨迹上机械臂及固定工具的最小禁止碰撞间隙，
  包含对环境、下层箱体、释放后的待放箱体与机器人自碰撞的相关检查。
  禁止接触的相机/雷达/附件仍在固定工具包络中；只排除显式定义的合法
  吸附/交接/推压接触对，不排除整箱或整类连杆。负载禁止碰撞同样是硬拒绝。
- 冲突时选机械臂碰撞裕量更大的方案，不用支撑加权分抵消较小的机械臂间隙。
  碰撞裕量相当时，再比较支撑裕量；几何误差/距离查询精度与相当判定容差
  必须明确配置，不用浮点噪声决定优先级。支撑子指标的进一步并列处理
  公开记录，不引入复杂度/耗时优化或隐藏权重。
- MotionPlan 记录 robot_clearance_min_m 及发生的阶段、轨迹时刻和碰撞对象对；
  payload_clearance_min_m 独立记录，不能用工具合法接触的零距离污染评分。
  接触排除/分离距离的证据不足时不得伪造裕量或宣称已验证。
- SolutionSelector 返回比较字段、阈值/误差与选择原因。行为验证包含：
  两方案都合格但支撑/机械臂间隙互有优劣时选择机械臂间隙更大者；支撑
  不合格或任一禁止碰撞均拒绝；合法推压接触不被误判为全臂零间隙；
  释放后箱体仍进入机械臂绕行/撤回碰撞检查。

本轮只讨论与更新设计，不启动开发或实验。以下数值是用户授权拟定的第一版

### 16.1 两种支撑几何分别输出

对刚性箱底 B 与共面、朝上的有效支撑面片，定义：
- contact_patches：箱底平面内满足接触高度容差的区域并集，含 holes；
  contact_area_m2 与 contact_area_ratio=area(union patches)/area(B)；
  缝隙/未知始终不计面积。几何预测明确标记 source=predicted_geometry。
- stability_support_polygon：这些接触区域在箱底平面上的凸包，用于无推力的
  准静态抗倾覆检查；COM 投影位于多边形内且最小边界距离 >= 配置裕量。
  跨缝时可以有有效抗倾覆支撑，但不会虚增实际接触面积。
- physics_contact_observation：仿真实际接触点/法向/间隙/接触对象对，以及
  观测箱体位姿。离散接触点的凸包不能冒充实际压力接触面积；记录 geometric
  overlap estimate、contact-point hull 与其来源，实际受压面积不可测时输出
  not_evaluated，而不是宣称取得了面积真值。未来真实系统同样保留来源/误差。

该支撑多边形只在 V1 刚性、共面、有可用承载支撑且重力主导条件下使用。
凸包不证明跨大洞时箱体不会弯折，也不证明施加推力后不会倾覆/带动下层。
推入期间检查箱体姿态/支撑随进度变化，并由物理实验单独验证推力影响。
新增跨 4mm 缝的案例：实际面积扣除缝隙，COM 经过缝隙时不自动判为失稳；
COM 越出支撑多边形则拒绝。平面误差与软/不共面超范围明确拒绝。

### 16.2 当前实验边界及精确表面

第一轮为 ideal_input_joint_motion_physics：仿真源提供准确箱体/场景信息，
通过显式 ideal_sim_fixture 适配器输出与真实链路一致的 OCC、SurfaceGeometry、
BoxState/GraspInput 字段；不直接输出答案 pose/轨迹，算法不按场景 ID 特判。
真实 RGB-D 接入及误差/遮挡/停止响应验证安排在后续 measured_input 阶段。
理想输入/状态反馈可来自仿真，但标签与结果不能冒充相机或真机验证。

OCC 用于空间占据，精确的共面表面几何独立用于接触高度和接触区域；不把
occupied 栅格上边界当作真实表面。两者关联同一 snapshot/geometry identity。
后续真实输入需从合法表面测量产生同一契约；实现误差能力未验证时拒绝接触
精度声明。理想反馈依然走统一 BoxObservation 接口，不能直接驱动物体。

PlanningContext/ContextBuilder 改称 PlanningInputs/PlanningInputsBuilder，
它们仅为一致输入与校验，不是 agent。外部第一版保留 plan(inputs, cancel,
progress_callback)->SolutionSet 和现有执行边界；枚举用内部迭代器，暂不为

所有权、配置版本与过期检查保持。OCC 五秒查询句柄仍只用于有界数据导出。

### 16.3 释放判据先实现观测，再做独立校准实验

用户允许在开发后以实验校准释放条件。开发时必须提供可配置的几何接触
判据和数据采集接口，不能把“未标定”实现为无条件释放。
首轮交接的几何预测门槛仍为 area_ratio>=0.60、COM margin>=0.020m。
到达交接位置后，理想仿真 profile 检查箱底与指定支撑表面的法向间隙 <=1mm、
无超过 0.5mm 的物理穿透；实际 box-support 接触观测持续 >=0.10s，然后释放。
以上为实验起点值，若求解器噪声无法满足先记录校准结果，不静默放宽。
不使用接触力/关节力矩作控制反馈；仿真接触信息是理想实验诊断/门控能力，
未来相机方案需另行实现等效观测或重新界定可执行范围。

解除真空且停止原 backend 的 kinematic follow 后，panel 先脱离再撤到不承重
位置；从 panel 与箱体分离开始计 3s 稳定观察窗，记录释放至撤出全过程。
稳定实验允许的观测误差界先设：目标箱水平漂移<=2mm、沉降<=2mm、转角<=0.5deg；
无持续工具承托、无侧壁托住/卡住、无掉落或异常穿透，否则不算支撑成立。
实测偏离“释放后不沉降/不倾斜/不滑动”假设按失败或假设失效记录。

释放校准采用独立实验 fixture，不是生产 planner 自动降低门槛：
- 同一 carryon、原始工具/下层场景、几何中心 COM；两个插入朝向 0/90deg。
- 扫描几何接触面积比例 0.40..0.80，步长0.05；每点3次重置重复，默认54单元。
- 每次报告实际比例、COM margin、实际接触、脱离条件与结果；60%/20mm 以下
  单元标为 diagnostic_outside_policy，不作为已认证动作解，更不注入三解计数。
- 因 panel 无法撤出/交接不可达的点记 geometrically_unavailable，不能算稳定
  或不稳定样本；该类实验可先采用明确的释放测试夹具，但不能宣称全臂可达。
- 在已观察稳定/不稳定区间按1%步长细化，每点3次，不假设跨缝多接触单调。
- “最小”仅报告该朝向/材料/质量/接触布局下最小已测且3/3稳定的比例与区间；
  不是通用阈值，也不是统计可靠性认证。少于3个有效样本为 not_evaluated。
- 初轮保持场景摩擦配置0.8，不在阈值实验同时改摩擦；后续固定选定条件单独
  扫描0.4/0.6/0.8作敏感性研究。参数是声明的仿真输入，不是 RGB-D 推断。

面积比例不是唯一解释量；若无法在当前 panel 退出限制内形成稳定区间，应
报告实际几何限制，不能仅继续调低支撑阈值来凑可行解。

### 16.4 直线箱体参考轨迹与物理执行

第一版采用 constant_orientation_straight_push。对 push progress s∈[0,L]：
  p_box(s)=p_handoff+s*d，R_box(s)=R_handoff。
d 为支撑平面内的单位向量，指向最终位姿；固定 panel 接触姿态的 nominal
运动方向与 d 一致。约束接触面法向与推压方向匹配，不能仅凭 TCP 移动方向
就断言箱子一定同向等速。该模型是参考/几何预测，不是物理定律。

新增 BoxMotionReference（start/end、d、L、orientation、progress/time mapping、
model_id、假设与有效范围）和 BoxObservation（pose、stamp、source、误差）。
机器人轨迹与名义箱体位姿按同一进度/时间关联。每个场景检查状态将释放后
箱体放在该名义位置，检查整箱扫掠、支撑、panel 接触与完整机械臂；不能保持
handoff 静态障碍同时将全箱碰撞屏蔽。物理执行仅发机器人轨迹，通过真实
panel 接触推动箱子，绝不设置箱体 pose 或重新吸附制造直线运动。

理想观察监测实际推进量、横向误差、yaw/roll/pitch、接触丢失、箱体与下层
运动。第一版只在原直线方向执行/暂停/停止，不引入横向修正、重新接触或
摆动推入。超差即停止并记录；停止全过程仍计入碰撞/位移验收。下一阶段
若实验表明有必要，再实现视觉位姿反馈的速度调节或 MPC，需重新校验轨迹。

公开研究依据（仅说明可选路线，不证明本 ULD 工况可行）：
- MIT Bauza/Hogan/Rodriguez, CoRL 2018：解析或 GP 推动模型配 MPC，物体位姿
  由 Vicon 相机系统跟踪，不能说其结果已验证腕载 D555 的遮挡/精度条件。
  https://proceedings.mlr.press/v87/bauza18a.html
- Columbia / Toyota Research Institute / MIT Diffusion Policy：视觉条件加
  滚动时域动作，真实 Push-T 是公开研究示例，需要示范/训练与单独泛化验证。
  https://diffusion-policy.cs.columbia.edu/
- 第一版不引入学习策略或 MPC，先测定直推预测在哪些条件成立。公开研究
  演示不等于公司已经量产无触觉 ULD 推箱系统。

### 16.5 接触与碰撞评分分开

通过硬约束再评分。记录三类量：
1. robot_noncontact_clearance：非预期接触对的全轨迹最小间隙和见证。
2. intended_contact_trace：指定面/patch 的接近间隙、法向、阶段、持续时间、
   穿透与脱离；接近阶段禁止穿透，到接触阶段只允许声明 patch/法向和容差。
3. payload_clearance/support_trace：箱体对禁止对象的间隙、接触面积比例、
   支撑多边形与 COM margin 随路径变化。

指定接触对在受约束的 approach/contact/withdraw 区间不进入第1项排名，但
第2项继续独立验证；panel 其他部位/侧面仍是禁止碰撞。不能只用整对象 ACM
放行来替代 patch 级验证。无接触间隙见证时输出未验证，不产生合格方案。

先要求所有门槛通过，按 robot_noncontact_clearance 降序；相差<=1mm 时
视为同档，再按最小 COM margin、最小支撑比例排序；仍同档按稳定 candidate_id
排序。相同起始姿态限制所有路径分数时如实报告并列，不删掉真实危险段。
复杂度/耗时不作为优选目标。排序正例必须能区分不同非接触机械臂间隙。
