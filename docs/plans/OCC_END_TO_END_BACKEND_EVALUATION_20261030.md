## 2. 公平比较与全链路计量

### 2.1 两种比较口径

| 口径 | 输入及配置 | 可得结论 |
|---|---|---|
| 共同全射线 | 两侧相同有效端点、真实原点、时间戳、ULD 几何和分辨率；处理全部有效射线，OctoMap `discretize=false` | 同工作量下后端成本、质量和资源比较 |
| 当前部署 | 各自冻结部署配置，记录实际保留端点、射线及更新格数；网格保留现有射线采样设置 | 当前系统实际响应能力，不据此宣称算法加速比 |

共同输入由一份冻结生成器产生；光学 Z 过滤和同时间戳坐标变换只执行一次，计入共享预处理成本。网格全射线档使用已有配置入口，使上限覆盖全部输入，并以实际射线计数验证，不能仅凭参数认定。

共同观测地图均由观测序列建立。箱数代表场景中的真实几何负载，不向其中一侧额外注入几何锁或实例先验。现有 `AddBox/remove/instance` 等能力另列产品兼容性测试。

### 2.2 统一事件与指标

每条记录包含 `run_id/input_id/request_id`、完整快照身份、进程与线程、单调时间、终态和版本。覆盖：

1. 输入就绪、预处理结束、发送、服务接收、写入返回。
2. 融合、派生维护、快照准备、导出排队、编码、哈希、写文件、发布。
3. 副本接收、校验、重建、READY，以及查询发送、回调、结果。
4. surface/账本被 planner 接纳、ComputePlacement 开始与返回。

没有精确 commit 事件时保留其时间区间；只能测到的“READY观测−写返回”按原名报告，不能替代精确传播时延。异步阶段允许重叠，端到端耗时直接测量，不用各段中位数相加。

同时报告墙钟、线程/进程 CPU、实际处理工作量、排队、缓存命中、重建/哈希字节、RSS/PSS及派生资源峰值。所有终态和成功子集分别统计，失败与未送达留在分母。

### 2.3 语义可比性

- 网格按 b33 和独立 oracle 检查既有事实、操作与读取合同；OctoMap 按其冻结概率、射线和域 oracle 检查。
- 两后端比较 unknown/free/occupied 分布、共同格分类差异、surface 高度差及域外写入；不同概率模型不要求 digest 全等。
- OctoMap 缺少实例操作、距离服务或 planning 合同时标 `unsupported`，不得用临时替代算法拼出性能数字。
- OctoMap surface 尚未证明满足 planning 支撑合同，本轮不接入 ComputePlacement；完整选位链验收针对网格候选。

## 3. 测试矩阵与判门

### 3.1 A. 正确性、增量与恢复

沿用冻结清单完成：180,000条网格 oracle、既有316项及新增相关回归、18组/612对 placement 响应对照、72组写入回归、198组取证检查。新增测试不得静默跳过；重复覆盖可复用同版本、同输入的可追溯结果。

补齐当前 fastpath 受影响的完整性边界：指针变化、正文摘要不符、重启/resync重验、载荷变化、旧句柄跨代稳定。稳定指针下正文原位损坏的检测时机须单独报告，不能沿用旧即时检出结论。

增量输入固定为重复 operation、相同观测新时间戳、概率饱和、稀疏变化、metadata-only及reset六类，每类30次；区分“事实未变”和“分类未变”。未变对象复用、变化对象传播、工作计数及快照结果均须正确。

### 3.2 B. 后端性能矩阵

| 矩阵 | 组合与样本 |
|---|---|
| 共同全射线 | 3分辨率 `{1,2,5}cm` × 3箱数 `{0,5,20}` × 2 hull × 2点数 `{30k,100k}` × 2 outside `{0.5,0.9}` × 2 crossing `{0,0.5}`，共144组/后端 |
| 当前部署 | 上述分辨率、箱数、hull、点数组合，outside=0.5、crossing=0，共36组/后端 |
| 冷启动 | 36组当前部署配置，每组30次新进程，分别测首帧、首次surface及立即重复读取 |

每组3帧预热＋30帧评分，保持累计地图历史；两后端按组交替执行，输入前缀一致。outside/crossing用独立几何判定核验实际类别；分别记录首次、变化后及缓存命中的查询成本。

每组报告更新、acquire、ROI、surface的median/P95/max、CPU/帧和峰值资源。原O6性能门继续显示；超过门限形成性能 FAIL，但仍可完成其余比较组。正确性错误、崩溃或资源失控停止受影响配置。

### 3.3 C. 真实选位业务链

18组：3分辨率 × 3箱数 × 2 hull，每组3次预热＋30次评分。冻结同一 planner、结构搜索配置、atlas及Attachment输入；覆盖结构命中、路线拒绝后续取、网格回退和预算截断的既有用例。

每次查询有明确目标地图身份，等待 planner 接纳相应 surface和账本，再通过真实 ROS 服务发起请求；验证实际求解读取的身份固定。继续统计端到端“输入就绪→选位结果”和实际各阶段，避免把副本查询成功误认为 planner 已消费新地图。

业务硬门：

- 身份、事实、支撑/倾角/hull/间距等硬门正确，错身份和假合法容忍为0。
- 有界获取最新目标快照≤2s；单次求解固定快照、预算不重置。
- ComputePlacement 客户端往返 P95≤5s、max≤20s；不将地图等待藏入求解耗时。
- surface/snapshot P95≤100ms、max≤250ms。
- 选位结果与冻结基准同输入对照成立；覆盖不完整必须具名返回，不能报箱满。
- 更新吞吐和输入到选位总耗时完整报告，本轮不另设相机帧率或整条观测链的硬时限。

### 3.4 D. 持续运行与压力

- **业务并发**：两后端分别运行1cm倒角、0/5/20箱、每配置120s×3。写入完成即提交下一帧；查询链以1Hz运行 acquire→ROI→surface→release。网格侧另按 `t=3+6k` 执行20次有界获取及真实选位请求。
- **旧压力档**：保留网格summary10Hz、ROI5Hz、distance256 2Hz、surface1Hz，以及固定2Hz写入的原C2规则；0/5/20箱各120s一次。
- **OctoMap压力档**：沿用已冻结O7正常与过载恢复程序，单独判定，不与不同查询集合求加速比。

业务查询每类至少30次成功，完整覆盖120s；所有计划请求均有记录。业务1Hz查询链要求零漏发和原查询时延门。旧压力档的distance256 P95≤50ms、零漏发等继续判定，但其失败不阻止业务与后端比较结果发布。

## 4. 统计、资源和执行程序

- P95采用 `ceil(0.95*n)-1`，30条取第29条；每组至少30成功样本，缺样为 `not_evaluated`。不事后剔除边界样本，不合并不同组掩盖失败。
- 正确性零容忍；三次持续窗逐次通过才签该有限矩阵通过，不推断长期100%可靠。
- 写入回归保留P95≤b33×1.10、max≤b33 max×1.20+20ms。取证同路径ON/OFF采用30对平衡AB/BA，P95比≤1.10、记录身份join完整。
- 部署进程合计RSS≤2GiB，派生唯一物理资源≤512MiB，init/reset≤30s；共享对象去重，独立副本分别计费，短命缓冲纳入峰值。缺归属记未知。
- 持续运行health间隔<1s；现有frame-runtime链零lease失效。OctoMap没有对应lease接口时记不适用。
- 先完成工具行为测试：错误身份、漏请求、全拒绝、迟到成功、缺提交、快慢写、资源超额和受控故障重放；工具必须能区分健康与错误。
- 预演后冻结 `COMMANDS.sh`、完整manifest和工具SHA。统一持 `/tmp/elfin-occ-backend-perf.lock`；每run记录外部负载、CPU/线程配置、软件版本及文件系统。
- 顺序为：版本和能力核对 → 正确性与资源代表组 → 真实业务链 → 共同后端矩阵 → 部署/冷启动矩阵 → 持续运行与压力 → 剩余回归矩阵。
- 性能失败完成当前有界组后继续独立组；正确性失败停止依赖该结果的测试。产品修复另交付，评分期间不修改受验产品。
- 每个子进程最长30分钟，单请求/操作超时30s，持续窗另有30s排空；超时保留故障证据，不自动补跑择优。
